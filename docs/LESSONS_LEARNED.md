**Дата инцидента:** 14 августа 2026 г.  
**Проект:** `projects/pole_chudes_capital` (Капитал-шоу Поле Чудес: Premium Edition)  
**Участники:** Порфирий Петрович (Оркестратор), Сергей Николаевич (Руководитель), QA Engineer, Software Engineer  
**Статус инцидента:** Исправлен, уроки извлечены и внесены в регламент конвейера MetaGPT.

## 1. Описание инцидента

После выпуска релиза **v8.0.0** пользователь столкнулся с тем, что:
1. Кнопка «🏛️ Музей» не реагировала на клики;
2. Кнопки «Вращать барабан» и «Назвать слово» оставались неактивными (серыми / disabled);
3. Приложение выглядело заблокированным или зависшим.

При этом автоматический тестовый сьют QA инженера рапортовал о **100% PASS** (15 из 15 тестов пройдены).

---

## 2. Корневые причины (Root Causes)

### 2.1. Иллюзия 100% покрытия мок-тестами (Unit Test Mock Bias)
- **Что произошло:** Тестовый сьют `tests/game.test.js` запускался через `node:test` с синтетическими моками глобальных объектов:
  ```javascript
  global.document = { getElementById: () => ({ ... }), createElement: () => ({ ... }) };
  ```
- **Следствие:** Тесты вызывали методы `new Game()`, `game.init()`, `museumManager.buyPrize()` напрямую в коде Node.js. Они проверяли изолированную математику и переходы стейт-машины, но **полностью игнорировали реальный запуск точки входа `src/js/main.js` в браузере**.

### 2.2. Race Condition при загрузке ES-модулей (`DOMContentLoaded`)
- **Что произошло:** В точке входа `main.js` код инициализации был обернут в:
  ```javascript
  document.addEventListener('DOMContentLoaded', async () => { ... });
  ```
- В теге `<script type="module" src="js/main.js">` скрипты загружаются в режиме `defer`. В браузере событие `DOMContentLoaded` часто наступает **до** или **одновременно** с исполнением тела модуля.
- **Следствие:** Обработчик ожидал события, которое уже произошло. Метод `game.start()` никогда не вызывался в реальном браузере.

### 2.3. Блокирующий статический оверлей (`#loader`)
- В статическом HTML присутствовал оверлей `<div id="loader" class="loader-overlay">` с `z-index: 1000`.
- Так как `game.init()` не запускался из-за `DOMContentLoaded`, оверлей оставался на экране навсегда.

### 2.4. Начальное состояние стейт-машины (`NEXT_PLAYER_ANNOUNCE` vs `WAITING_FOR_SPIN`)
- Стейт-машина стартовала с промежуточного объявления перехода хода, державшего кнопки барабана и ввода слова в `disabled` до ручного клика по диалоговому окну.

---

### 2.5. Ловушка вложенного кэширования графа ES-модулей (Nested ES Module Cache Trap)
- **Что произошло:** При обновлении версии в `index.html` (`main.js?v=8.0.4`), вложенный относительный импорт `import { UI } from './ui.js'` в `game.js` не содержал версионного суффикса.
- Браузер скачивал свежий `main.js`, но для `ui.js` брал из своей оперативной памяти закэшированную версию до v8.0.0, где метода `showMuseumModal()` еще не существовало.
- **Следствие:** При клике на кнопку «🏛️ Музей» в консоли браузера вылетала тихая ошибка `TypeError: game.ui.showMuseumModal is not a function`. Модальное окно не открывалось, а пользователь видел отсутствие реакции на клик.

## 3. Почему QA тестировщик пропустил проблему

1. **Иллюзия «зеленых тестов» (Unit Mock Illusion):** Тестировщик запускал `node --test`, где Node.js читал свежие файлы с диска и выдавал 100% PASS, скрывая проблемы с кэшированием в реальном браузере.
2. **Отсутствие запуска реального браузерного движка:** Тестировщик не подключался к реальному браузеру (Firefox Gecko / Chromium) для физического клика по кнопкам.
3. **Отсутствие аудита консоли браузера:** Ошибки уровня рантайма браузера (`TypeError`) оставались незамеченными.

---

## 4. Внедренные системные исправления

### 4.1. В кодовой базе
1. **Синхронное версионирование графа модулей:**
   Все импорты (`game.js?v=8.0.5`, `ui.js?v=8.0.5`, `state.js?v=8.0.5`, `prizes.js?v=8.0.5`) версионируются единым кэш-бастером.
2. **Оборонительный inline-триггер в `index.html`:**
   ```html
   onclick="try{ if(window.openMuseum) window.openMuseum(); else document.getElementById('modal-museum').classList.remove('hidden'); }catch(e){ document.getElementById('modal-museum').classList.remove('hidden'); }"
   ```
3. **Smart Bootstrap в `src/js/main.js`:**
   ```javascript
   if (document.readyState === 'loading') {
       document.addEventListener('DOMContentLoaded', bootstrap);
   } else {
       bootstrap();
   }
   ```
4. **Удален блокирующий оверлей** из HTML, интерфейс открывается мгновенно.
5. **Прямой старт в `WAITING_FOR_SPIN`:** кнопки управления активны сразу при входе.

### 4.2. Сквозной робот-тест в реальном браузере (`tests/e2e_browser_test.py`)
- Создан тестовый модуль, использующий нативный протокол Marionette/WebDriver для управления реальным процессом Firefox.
- Автоматически проверяет: запуск, переход по URL, клик по кнопкам, удаление класса `hidden`, рендер всех 16 карточек трофеев, отсутствие ошибок консоли и сохранение контрольного скриншота.

## 6. Инцидент v8.1.0 — Обход шлюзов ревью (14 августа 2026)

### 6.1. Что произошло
В инкременте v8.1.0 (UI/UX Premium Refresh) Оркестратор (Порфирий Петрович) обошёл все три обязательных шлюза ревью:
- **Gate 1A** не был предъявлен Сергею Николаевичу на аппрув — Оркестратор счёл комментарии к `implementation_plan.md` достаточным подтверждением.
- **Gate 1B** не был предъявлен Никоглаю — Оркестратор немедленно запустил инженера после архитектора.
- **Gate 2** не был предъявлен Никоглаю — ответ «Continue» от пользователя был ошибочно принят за аппрув кода.

### 6.2. Почему это нарушение
Согласно `AGENTS.md` и `SOP_ORCHESTRATOR.md`, каждый шлюз требует **явной фразы-ключа**:
- Gate 1A: `«Approve PRD»` от Сергея Николаевича
- Gate 1B: `«Approve Architecture»` от Никоглая
- Gate 2: `«Approve»` от Никоглая

Комментарии к плану, «да», «продолжай», «Continue» — **не являются аппрувом шлюза**.

### 6.3. Системное исправление
- Обновлён `docs/SOP_ORCHESTRATOR.md`: добавлен раздел **MANDATORY REVIEW GATES — HARD BLOCK RULES** с точными правилами блокировки по каждому Gate.
- Правило зафиксировано: *пользовательский комментарий к `implementation_plan.md` ≠ Gate 1A PRD Approve.*
