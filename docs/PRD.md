# Product Requirements Document (PRD)
**Project Name:** Капитал-шоу "Поле Чудес: Premium Edition"
**Version:** v9.0.0 (Clean Room Rebranding, Three Bogatyrs & Yakvadratish Wardrobe Edition + Cloud Run Readiness)
**Mode:** Compact Mode (Hot-Seat Multiplayer + Persistent Meta-Progression + Wardrobe Customization + Cloud Native)

---

## 1. Original Requirements & Incremental Scope

### 1.1 Original Requirements (v1.0 - v7.0)
- Создание браузерной веб-игры "Капитал-шоу Поле Чудес" с акцентом на премиальный визуальный стиль (Glassmorphism, адаптивная типографика, плавные микро-анимации, центрированный барабан, pop-in эффекты).
- Формат игры: локальный мультиплеер **Hot-Seat** (за одним экраном с передачей хода между 3 игроками с персональными аватарами былинных героев).
- Строгая стейт-машина (State Machine) для полного исключения состояний гонки (Race Conditions) и защиты от некорректных действий игроков (Foolproof).
- Секторы барабана: Очки (100, 250, 350, 500, 750, 800, 1000), Банкрот (Б), Ноль (0), Плюс (+), Приз (П).
- Мини-игры: "Две шкатулки" (при 3 угаданных буквах подряд), "Супер-игра" (для победителя финала с таймером на 60 секунд).
- Интеграция виртуального Ведущего с портретом и репликами/подсказками к вопросам.
- Образовательный сбалансированный словарь на 500 реальных слов (5 категорий по 100 слов: «Животные», «Природа», «Сказки», «Изобретения», «Космос»), адаптированный для учащихся 4 класса, с фактами-подсказками и кэшированием сыгранных слов в `localStorage`.

### 1.2 Incremental Scope (v8.0.0 - v8.2.0)
- **v8.0.0 (Витрина подарков и Музей Капитал-шоу):**
  - Подсистема витрины подарков (Prize Shop) с покупкой призов за заработанные в раунде очки.
  - Полноэкранный Музей Капитал-шоу (Зал Славы / Trophy Room) с 4 градациями редкости (Common, Rare, Epic, Legendary), силуэтами заблокированных призов, персистентностью в `localStorage` (`pole_chudes_museum`, `pole_chudes_stats`).
  - Интеграция сектора «Приз» и Супер-игры с коллекцией Музея.
- **v8.1.0 (UI/UX Premium Refresh):**
  - Глубокий космическо-пурпурный градиент, типографика Google Fonts (`Russo One` + `Inter`), барабан 300px с сочной палитрой секторов, микро-анимации фокуса и статусов (`fadeSlideUp`, `auroraBorderGlow`).
- **v8.2.0 (Continuous Game Loop & In-Game Reset):**
  - Бесшовный перезапуск игры через `restartNewGame()` без перезагрузки F5, восстановление карточек игроков, очистка табло и генерация нового раунда.

## 2. Product Goals
1. **100% Legal Clean Room & Safe IP:** Полное отсутствие рисков нарушения авторских прав за счет использования оригинальной пародии (Леонид Яквадратиш) и фольклорных персонажей (Три Богатыря).
2. **Deep Player Engagement (Meta-Progression & Wardrobe):** Игроки мотивированы не только выигрывать призы в Музей, но и наряжать ведущего Леонида Яквадратиша в уникальные наряды, открываемые за победы и накопленные баллы.
3. **Rich Slavic & Retro Charm:** Теплая, душевная атмосфера народной телепередачи, сочетающая древнерусский эпос, самовары, сказочные артефакты и праздничные традиции.
4. **Enterprise Cloud Readiness:** Готовность к развертыванию одной командой в Google Cloud Run с субсекундным временем старта контейнера, высокой плотностью и нулевым потреблением ресурсов в простое.
5. **Rock-Solid Fault Tolerance:** 100% надежная стейт-машина, адаптивный Glassmorphism интерфейс, чистый ES6+ код без сторонних тяжелых зависимостей.

## 3. Detailed Use Cases (по Алистэру Коберну)

### UC1: Вращение барабана
*   **Primary Actor:** Активный богатырь (Илья Муромец / Добрыня Никитич / Алёша Попович)
*   **Preconditions:** Состояние `WAITING_FOR_SPIN`. Ход текущего игрока. Кнопка `🎰 Вращать барабан` активна.
*   **First Paint State:** При первой загрузке приложения кнопка вращения барабана разблокирована и готова к немедленному взаимодействию без необходимости кликов по сервисным плашкам.
*   **Main Success Scenario:**
    1. Игрок нажимает кнопку "🎰 Вращать барабан".
    2. Система переходит в состояние `SPINNING`, блокирует элементы управления (кнопки, клавиатуру).
    3. Запускается аудио-эффект трещотки барабана и CSS-анимация вращения с плавным замедлением (cubic-bezier).
    4. Барабан останавливается строго по центру выбранного сектора.
    5. Система переходит в состояние `EVALUATE_SECTOR` и передает управление соответствующему обработчику.
*   **Extensions:**
    *   *Спам-клики:* Игнорируются; кнопка немедленно переходит в disabled.
    *   *Ввод клавиш во время вращения:* Игнорируется.
*   **Postconditions:** Барабан остановлен на секторе, стейт обновлен.

---

### UC2: Ввод буквы
*   **Primary Actor:** Активный богатырь
*   **Preconditions:** Состояние `WAITING_FOR_LETTER`. Барабан остановился на секторе с очками (100–1000). Клавиатура разблокирована.
*   **Main Success Scenario:**
    1. Игрок выбирает согласную букву на экранной клавиатуре.
    2. Выбранная кнопка буквы переходит в disabled.
    3. Система выполняет поиск буквы в загаданном слове (`secretWord`).
    4. Буква присутствует в слове:
       - Все вхождения буквы открываются на табло с анимацией pop-in.
       - Воспроизводится звуковой сигнал открытия ячейки.
       - Игроку начисляются очки: `sectorValue * количество угаданных букв`.
       - Счетчик угаданных подряд букв `consecutiveGuesses` инкрементируется на 1.
       - Если слово не открыто полностью, игрок сохраняет ход и возвращается в `WAITING_FOR_SPIN`.
*   **Extensions:**
    *   *Буквы нет в слове:* Звуковой сигнал промаха, статус "Буквы X нет в слове!", `consecutiveGuesses = 0`, ход передается следующему богатырю (UC4).
    *   *Ввод гласной буквы:* Буква открывается на табло (если есть), очки не начисляются. Игрок сохраняет ход.
*   **Postconditions:** Табло обновлено, очки начислены, определен следующий шаг.

---

### UC3: Назвать слово целиком
*   **Primary Actor:** Активный богатырь
*   **Preconditions:** Состояние `WAITING_FOR_SPIN`. Игрок решает назвать слово без вращения барабана.
*   **Main Success Scenario:**
    1. Игрок нажимает кнопку "💬 Назвать слово".
    2. Система переходит в состояние `GUESSING_WORD` и отображает модальное окно с полем ввода.
    3. Игрок вводит слово и нажимает кнопку "Подтвердить".
    4. Введенное слово посимвольно совпадает с `secretWord` (без учета регистра):
       - Все ячейки на табло открываются с анимацией триумфа.
       - Ведущий Леонид Яквадратиш восклицает: *"Абсолютно верно! Победитель раунда — [Имя Богатыря]!"*.
       - Игроку засчитывается досрочная победа в туре (UC11).
*   **Extensions:**
    *   *Неверное слово:* Система выводит сообщение "Слово названо неверно! Вы выбываете из игры!", помечает игрока как `isEliminated = true`, затемняет его карточку и передает ход следующему богатырю (UC7, UC4).
    *   *Отмена:* Модалка закрывается, возврат в `WAITING_FOR_SPIN`.
*   **Postconditions:** Слово отгадано (победа) либо игрок исключен из текущего раунда.

---

### UC4: Передача хода (Hot-Seat Три Богатыря)
*   **Primary Actor:** Система / Богатыри (Илья Муромец, Добрыня Никитич, Алёша Попович)
*   **Preconditions:** Активный игрок ошибся буквой, назвал неверное слово, либо выпал сектор «Ноль» / «Банкрот».
*   **Main Success Scenario:**
    1. Система сбрасывает счетчик непрерывных угадываний `consecutiveGuesses = 0`.
    2. Определяется следующий по очереди богатырь, не имеющий статуса `isEliminated` (по кругу: Илья Муромец ➔ Добрыня Никитич ➔ Алёша Попович ➔ Илья Муромец).
    3. Отображается модальное окно "Переход хода": крупно выводится былинный аватар и имя следующего богатыря.
    4. Игрок подтверждает готовность кликом "Начать ход".
    5. Система переводит игру в состояние `WAITING_FOR_SPIN` для нового активного богатыря.
*   **Extensions:**
    *   *Остался 1 не выбывший богатырь:* Переход хода не требует модального подтверждения; богатырь играет соло.
    *   *Все 3 богатыря выбыли:* Переход в `GAME_OVER`.
*   **Postconditions:** Активный богатырь переключен, карточка подсвечена золотым ореолом (Aurora border glow).

### UC5: Сектор "Банкрот" (Б)
*   **Primary Actor:** Система
*   **Preconditions:** Барабан остановился на секторе "Б".
*   **Main Success Scenario:**
    1. Система фиксирует выпадение сектора "Б".
    2. Баланс очков текущего раунда у активного богатыря обнуляется (`score = 0`).
    3. Леонид Яквадратиш сочувственно произносит: *"Сектор Банкрот! Все богатырские очки сгорают!"*.
    4. Воспроизводится звук банкрота.
    5. Через 2 секунды автоматически инициируется передача хода (UC4).
*   **Postconditions:** Очки активного игрока равны 0, ход передан.

### UC6: Сектор "Ноль" (0)
*   **Primary Actor:** Система
*   **Preconditions:** Барабан остановился на секторе "0".
*   **Main Success Scenario:**
    1. Система фиксирует выпадение сектора "0".
    2. Набранные очки богатыря полностью сохраняются.
    3. Статус-бар выводит: *"Сектор НОЛЬ! Переход хода к следующему богатырю."*.
    4. Через 2 секунды инициируется передача хода (UC4).
*   **Postconditions:** Очки не изменились, ход передан.

### UC7: Выбывание игрока
*   **Primary Actor:** Система
*   **Preconditions:** Богатырь ошибся при назывании слова целиком (UC3) либо забрал приз в секторе «Приз» (UC8).
*   **Main Success Scenario:**
    1. Флаг богатыря устанавливается в `isEliminated = true`.
    2. Карточка богатыря визуально деактивируется (полупрозрачность, бейдж "Выбыл").
    3. Если остались другие активные богатыри, вызывается передача хода (UC4).
*   **Postconditions:** Количество активных участников уменьшено на 1.

### UC8: Сектор "Приз" (П) и вручение фольклорного подарка в Музей
*   **Primary Actor:** Активный богатырь / Леонид Яквадратиш
*   **Preconditions:** Барабан остановился на секторе "П".
*   **Main Success Scenario (Торг с Леонидом Яквадратишем):**
    1. Система переходит в состояние `PRIZE_BARGAIN` и открывает модальное окно сектора «Приз».
    2. Леонид Яквадратиш хитро подкручивает усы и предлагает выбор: *"Забрать сказочный приз из Черного Ящика или взять 1000 очков?"*.
    3. **Вариант А: Игрок выбирает 1000 очков:**
       - Начисляется +1000 очков.
       - Модалка закрывается, богатырь продолжает ход (`WAITING_FOR_SPIN`).
    4. **Вариант Б: Игрок выбирает "Взять ПРИЗ":**
       - Система выбирает случайный подарок из славянского фольклорного пула (например, *«Банка соленых рыжиков»*, *«Расписной электросамовар»*, *«Перо Жар-птицы»*, *«Сапоги-скороходы»*).
       - Отображается всплывающее окно *«В черном ящике был приз: [Название]!»*.
       - Приз записывается в постоянную коллекцию Музея (`localStorage`) с отметкой источника "Сектор Приз".
       - Богатырь с почестями выбывает из раунда (`isEliminated = true`, UC7).
*   **Postconditions:** Приз добавлен в Музей, богатырь покинул круг отгадывания.

    4. Буква открывается на всех позициях с анимацией pop-in.

### UC10: Мини-игра "Две шкатулки"
*   **Primary Actor:** Активный богатырь
*   **Preconditions:** Богатырь угадал 3 согласные буквы подряд (`consecutiveGuesses >= 3`).
*   **Main Success Scenario:**
    1. Игра приостанавливается, открывается модальное окно "Две шкатулки от Яквадратиша".
    2. Игроку предлагается выбрать левую или правую расписную шкатулку.
    3. В одной из шкатулок спрятаны 5000 очков, вторая пуста.
    4. При угадывании начисляется +5000 очков и звучит праздничный перезвон.
    5. `consecutiveGuesses` сбрасывается в 0, богатырь продолжает ход.
*   **Postconditions:** Бонус начислен (при успехе), игра возобновлена.

### UC11: Победа в туре и переход к награждению
*   **Primary Actor:** Система / Богатырь-победитель
*   **Preconditions:** Все буквы слова открыты на табло либо слово названо верно целиком.
*   **Main Success Scenario:**
    1. Система переходит в состояние `ROUND_WIN`.
    2. Запускается триумфальная анимация конфетти, победный джингл.
    3. Леонид Яквадратиш поздравляет богатыря с победой в туре.
    4. Обновляется статистика побед и суммарных очков в `localStorage`.
    5. Появляется модальное окно с предложением сыграть в Супер-игру (UC12).
    6. При согласии — запуск Супер-игры (UC12); при отказе — переход к Витрине подарков (UC13).
*   **Postconditions:** Победа зафиксирована, статистика сохранена.

### UC12: Супер-игра (Super Game)
*   **Primary Actor:** Богатырь-победитель
*   **Preconditions:** Победа в туре (UC11). Игрок согласился на Супер-игру.
*   **Main Success Scenario:**
    1. Система выбирает сложное слово с флагом `superGame: true`.
    2. Леонид Яквадратиш торжественно объявляет супер-вопрос: *"Внимание! На кону — былинный скакун или легендарный сказочный транспорт!"*.
    3. Игроку предлагается назвать любые 3 буквы (состояние `SUPER_GAME_SETUP`).
    4. Выбранные буквы открываются на табло, если они есть в слове.
    5. Включается 60-секундный таймер (`SUPER_GAME_PLAYING`).
    6. Игрок вводит слово до истечения времени.
    7. **Триумф Супер-игры (`SUPER_GAME_WIN`):**
       - Фанфары, победный салют.
       - Вручается супер-приз: **Легендарный богатырский конь Бурушка** с занесением в Музей.
       - Разблокируется эксклюзивный костюм для Леонида Яквадратиша: **Шлем космонавта** (Cosmonaut Helmet).

### UC18: Перезапуск новой игры (Continuous Game Loop & In-Game Reset)

### UC20: Развертывание в Google Cloud Run и проверка работоспособности (Cloud Readiness) — [НОВЫЙ В v9.0.0]
*   **Primary Actor:** DevOps / Cloud Engineer / Системы мониторинга Google Cloud
*   **Preconditions:** Проект упакован в Docker-контейнер и развернут в сервисе Google Cloud Run.
*   **Main Success Scenario:**
    1. Google Cloud Run запускает контейнер и передает динамический номер порта через переменную окружения `$PORT` (по умолчанию 8080).
    2. Точка входа Nginx с помощью шаблонизатора `envsubst` подставляет `$PORT` в конфигурацию `nginx.conf` и запускает веб-сервер.
    3. Система мониторинга Google Cloud выполняет HTTP GET запрос на эндпоинт проверки работоспособности: `GET /healthz`.
    4. Nginx мгновенно возвращает ответ с кодом `HTTP 200 OK`, заголовком `Content-Type: application/json` и телом `{"status":"healthy","version":"v9.0.0"}`.
    5. Google Cloud Run переводит ревизию в статус `Ready` и направляет входящий пользовательский трафик на порт сервиса.
    6. Браузерные клиенты получают все статические ресурсы (HTML, CSS, JS модули, JSON словарь, PNG аватары) со сжатием Gzip и правильными заголовками кэширования `Cache-Control`.
*   **Extensions:**
    *   *Переменная PORT не задана:* Nginx автоматически использует дефолтный порт 8080.
*   **Postconditions:** Сервис доступен в Google Cloud Run по HTTPS с автоматическим масштабированием до 0 в простое.

## 9. Google Cloud Run Deployment Architecture

```
                                 Google Cloud Platform
                        +---------------------------------------+
                        |           Google Cloud Run            |
                        |                                       |
    HTTPS User Traffic  |    +-----------------------------+    |
    ------------------->|--->|   Container: Nginx Alpine   |    |
   (Port 443 / SSL Term)|    |   - Listening on $PORT      |    |
                        |    |   - Static SPA assets       |    |
                        |    |   - Gzip compression        |    |
                        |    |   - /healthz -> 200 OK      |    |
                        |    +-----------------------------+    |
                        +---------------------------------------+
```

### 9.1 Спецификация Dockerfile
- **Базовый образ:** `nginx:alpine` (минимальный вес образа < 30 МБ, нулевые уязвимости).
- **Конфигурация портов:** Автоматическая трансляция переменной окружения `$PORT` в конфигурацию виртуального хоста через стандартный механизм `docker-entrypoint.d/20-envsubst-on-templates.sh` или встроенный скрипт запуска.
- **Размещение статики:** Копирование директории `src/` в `/usr/share/nginx/html`.

### 9.2 Спецификация `nginx.conf`
- **Gzip Сжатие:** Включено для `text/html`, `text/css`, `application/javascript`, `application/json`, `image/svg+xml`.
- **MIME-типы:** Строгая отдача ES6 модулей с `Content-Type: application/javascript; charset=utf-8`.
- **Healthcheck Эндпоинт `/healthz`:**
  ```nginx
  location = /healthz {
      access_log off;
      default_type application/json;
      return 200 '{"status":"healthy","version":"v9.0.0"}';
  }
  ```
- **Кэширование:**
  - `index.html` — `Cache-Control: no-cache, must-revalidate`.
  - Версионированные статические файлы (`?v=9.0.0`) — `Cache-Control: public, max-age=31536000, immutable`.
- **Защитные заголовки:** `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`.
